## 日常开发流程

```bash
# 1. 改代码
# 2. 本地跑测试（必须全过）
python -m unittest discover tests

# 3. 本地看效果
python app.py        # 或双击 启动 SkillRadar.bat

# 4. 提交并推送（Streamlit Cloud 会自动重建）
git add -A
git commit -m "feat: 说明这次改了什么"
git push origin main
```

推送后约 1–2 分钟，原网址自动更新为新版本，**URL 不变**。

## 出问题怎么回滚

### 方式一：只回退远程（最快，不影响本地）

```bash
git push origin stable:main --force
```

把 `main` 强制指回 `stable` 的版本。Streamlit Cloud 会自动重建，
站点在 1 分钟内回到已知可用的状态。

### 方式二：本地也回退

```bash
git checkout main
git reset --hard stable
git push origin main --force
```

### 方式三：只撤销某一次提交

```bash
git log --oneline          # 找到要撤销的 commit
git revert <commit-hash>   # 生成一个反向提交
git push origin main
```

### 方式四：实在不行，在 Streamlit Cloud 里切换分支

1. 打开应用页面右下角 **Manage app**
2. 找到 **Settings → General → Branch**
3. 把 `main` 改成 `stable`，保存
4. 应用会按 `stable` 分支重新部署

这样连 git 都不用动，网页上点两下就恢复。

## 什么时候把 stable 往前推

当一个版本**在公网验证通过、且确认不再回退**时，把 `stable` 移到该 commit：

```bash
git branch -f stable main
git push origin stable --force
git tag -a v1.1-<说明> -m "..." && git push origin v1.1-<说明>
```

**建议时机**：录完演示视频之后、提交前一天。

千万不要在有演示的前一晚大改 `main`——如果非改不可，先在本地或新分支验证。
