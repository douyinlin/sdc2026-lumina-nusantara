## 设计决定与理由

| 决定 | 理由 |
| --- | --- |
| 保留 Streamlit/Python 单进程结构 | 有可用代码和测试；后端函数在服务器计算，最小版无需再加 HTTP 服务 |
| 默认限定 3 个岗位、6 项技能和 1 个虚构用户 | 使演示流程清楚且能逐项核算，控制本次范围 |
| 用规范化集合计算覆盖率，保留完整分数 | 大小写、空格及双方重复技能不会重复计数；1/3 保留精度到显示时再格式化 |
| 空用户技能显示 0%，空岗位要求报错 | 用户可以从零开始，同时避免无分母岗位制造误导性结果 |
| 无真实趋势、课程时明确说明 | 不伪造来源、日期、课程、费用、就业预测或报销资格 |
| 保留旧功能为可选实验模式 | 保全既有有效工作；不把实验分数当技能覆盖率或录用概率 |
| 修复旧双情景按岗位名称关联 | 原来按两份已排序列表的位置配对，可能把不同岗位放在同一比较行 |
| 把样例和旧实验目录移出 UI 常量区 | `data/demo.json` 与 `data/experimental.json` 各有明确用途，CLI 与最小网页复用同一数据 |
| 显式安装依赖、固定 pip 版本清单 | 不在应用启动时联网装包；减少私人运行路径依赖，便于复现 |
| 不使用数据库、认证、支付或新增真实上传 | 本次只需跑通技能差距，不扩大基础设施和个人资料处理范围 |

旧实验情景仍保留：moderate 使用既有任意权重；fast 将模拟趋势分量权重乘 2 后归一化。它们是算法敏感性示例，**不是未来趋势预测**。SDG 仅为既有示例标签，尚无岗位与技能的逐项理由或贡献评估。
